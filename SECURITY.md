# Security reporting

The current public distribution is the 3.2.4 Intel Mac preview. It is ad hoc signed and not notarized; known limitations are recorded in the release notes. A supported general-distribution signing policy has not yet been established.

For a vulnerability, use the repository Security tab's private reporting option if available. Otherwise open an issue containing only a request for a private reporting channel, without exploit details, credentials, patient data or confidential files. The maintainer can arrange a channel before sensitive information is exchanged. No dedicated security email or response-time guarantee is asserted here.

If a token/password was exposed, revoke or rotate it at the issuing service. Never put it in a Git URL, issue, screenshot, model note or pull request. Public logs and source archives should contain synthetic identities only. Do not upload the Amua support directory or OS credential-store exports.
