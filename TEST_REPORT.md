# Windows 3.2.4 verification

The Windows release workflow builds and tests the complete portable application on `windows-2022`. It refuses publication unless every required group succeeds. `windows-checks.json`, `package-verification.json` and `build-provenance.json` accompanying the release identify the actual results and application file hashes; the workflow logs retain test counts and explicit skips.

Checks cover native GUI startup and second-instance activation, MCP status without terminating Java, Unicode paths and poisoned host Python environment, Windows Credential Manager chunking/rotation/deletion, native file locks, supervised process termination, output limits and confidential snapshot cleanup after forced termination. Packaged workflow intake/save/reopen and controlled image review run the real Java engine: Drug A = $850/1.55 QALYs; Drug B = $1520/2.20 QALYs.

The package verifier checks all 717 application classes and requires all 145 tree/Markov/math classes to remain byte-identical to the checked Intel candidate. Three changed classes implement Windows save handling and MCP launch instructions. Eight original-engine decision-tree/Markov outputs must match the original application exactly. Fourteen Java atomic-save checks and native Java sidebar/clipboard/drop/approval/progress checks also run.

Provider regression discovers 124 tests: two private-workbook tests are explicitly skipped because their data is not distributed; three POSIX process/lock tests are replaced by the native Windows lock/job/output tests. Skips are not counted as passes. Workflow tests cover public intake, mixed formats, scanned-PDF OCR, resumable OCR, bounded inventories, writer-death recovery and Nashorn metadata round trips. The Windows OCR test uses the actual OS English OCR engine; unavailable OCR components block that check rather than receive a waiver.

An early native run found a missing startup icon, POSIX-only permission/helper assumptions, and a sanitized environment missing Windows SystemDrive. Those were corrected; the audit is in RED_TEAM.md. Build actions use pinned Node.js 24 releases.

These are synthetic and controlled-response checks. They do not establish live account entitlement, remote image recognition, scientific validity, physical clipboard/drop behavior on each desktop, Windows 10/11 clean-machine acceptance, every OCR language, network filesystem behavior or power-loss durability. The app is an unsigned preview. No actual user credentials, private workbooks or model inputs are published.

Native run [43800841798](https://github.com/rejie-coder/amua_adapted/actions/runs/43800841798) passed all 19 groups before the two additional workflow suites were added: 12 native Windows tests passed, provider regression reported 124 tests with five explicit skips, and all four actual/helper OCR checks passed. The publishing run repeats those gates and adds the two workflow suites; its downloadable reports are authoritative for the released bytes.
